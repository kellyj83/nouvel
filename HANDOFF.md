## Current Understanding Of Nouvel

Nouvel publicly describes itself as outbound infrastructure for high-growth companies:
https://nouvel.ai/

Its public workflow runs from market signal to qualified reply:

- lead research and qualification;
- buying-signal tracking;
- sending infrastructure;
- personalised outbound outreach;
- automated follow-up;
- reply routing with account and message history.

The client's team takes over when a prospect replies or books a meeting. There is no
current evidence that Nouvel's agents conduct voice sales calls on behalf of customers.

The conversation with Shutian also described agents handling work after human-led sales
or kickoff calls, including follow-up, contract reminders, payment collection, onboarding
and internal updates. It is still unclear whether this is:

- part of Nouvel's customer-facing product;
- an internal Nouvel workflow;
- a custom client service;
- or future product direction.

This is an important question for the next conversation with Shutian.

## Product Conclusions

An audio-based engagement score is technically possible. It could combine transcript
meaning, pauses, speaking dynamics, tone and CRM context to prioritise follow-up.
However, it is probably not Nouvel's most important first problem because it applies
after a live meeting, whereas Nouvel's public product focuses mainly on reaching and
qualifying prospects before that meeting.

Problems currently judged to be more central to Nouvel are:

1. Qualified-reply triage: book, clarify, nurture, disqualify or escalate.
2. Converting positive replies into booked meetings quickly.
3. Improving the quality and explainability of buying signals.
4. Reliable handoffs containing account history, intent and recommended next steps.
5. Post-call execution from transcript to CRM, follow-up, contracts and onboarding.
6. Audio engagement scoring as a later enhancement.

The strongest next prototype would be a qualified-reply triage agent. It should read an
email thread, account context and qualification rules, then choose one constrained next
action and provide evidence for its choice.

## Prototype Architecture

The current prototype intentionally separates uncertain AI judgement from predictable
software operations.

`sales_agent.py`:

- reads `Chat with Shutian transcript.txt`;
- asks one OpenAI agent for a structured sales-call report;
- writes `Shutian agent sales report.md`.

`sales_pipeline.py`:

- asks the model to extract call information and choose exactly one action;
- supported actions are `follow_up`, `escalate_to_human`,
  `request_more_information` and `no_action`;
- ordinary Python then saves the structured decision;
- ordinary Python updates a local mock CRM record;
- ordinary Python creates a mock Slack post;
- ordinary Python follows the selected branch and writes `next action.md`.

The model therefore makes one uncertain decision. It does not directly update Slack or
a CRM. Real API adapters can later replace the local file-writing functions.

## Current Result

The pipeline classified the Shutian conversation as an exploratory recruitment
conversation rather than a customer sales opportunity. It recommended `follow_up` with
95% confidence because both participants discussed reconnecting after Jonathan explored
agent tools.

The generated result should be treated as a demonstration of the architecture, not as a
validated sales decision system.

## Environment

The project was tested with Python 3.9 and these pinned dependencies:

```text
openai-agents==0.8.4
openai==2.44.0
pydantic==2.13.5
eval-type-backport==0.4.0
```

Recreate the environment after moving or copying the project. Do not reuse the old
`.venv`, because virtual environments can contain absolute paths.

```bash
cd "/path/to/Nouvel AI"
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python sales_pipeline.py
```

The pipeline securely prompts for an OpenAI API key if one is not already available.

## Suggested Next Build

Build a small qualified-reply triage prototype with synthetic inputs before connecting
any live systems.

Suggested input:

- prospect reply and previous email thread;
- account and campaign context;
- explicit qualification and exclusion rules;
- optional CRM history.

Suggested structured output:

- classification: positive, objection, question, referral, unsubscribe or unclear;
- next action: book, answer, clarify, nurture, disqualify or human review;
- confidence;
- evidence from the reply and account context;
- draft response;
- whether human approval is required.

Keep CRM writes, email sending and calendar booking deterministic and approval-gated.
The agent should recommend actions, not silently perform irreversible operations.
